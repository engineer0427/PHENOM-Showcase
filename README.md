# PHENOM / CFEA — 검증 노트 (보관용)

> 2026-10-21 기준. 이 프로젝트는 검증 결과에 따라 **특허 정규출원을 하지 않고 접기로 결정**했다.
> 코드는 기록으로만 남기며, 아래 문제들이 해결되지 않은 상태다. 수치와 주장을 인용하지 말 것.

## 무엇을 만들려 했나

명령어 없이, 대칭 결합을 가진 노드들이 연속 상태 방정식
`dx/dt = -γx + W·act(x) + θ` 을 따라 에너지가 낮은 상태로 수렴하는 전용 하드웨어(CFEA).
수렴하면 클록을 끄고, 결합값 쓰기 때 대칭(W_ij = W_ji)을 하드웨어로 강제하는 구조를 포함.
가출원: 2026-08-05 (참조번호 TB20260411).

## 확인한 문제

### RTL (`cfea_top.v`, `cfea_top_tb.v`)
- **문법 오류로 컴파일 불가**: 175행 `DT_INT = 16 me16'h000D;`
- **부호 있는/없는 수 비교 버그**: PE 배열의 활성화가 `x > 16'h0100` 처럼 부호 없는 상수와 비교 →
  Verilog 는 양쪽을 부호 없는 수로 비교하므로 음수는 +1.0, 작은 양수는 −1.0 으로 바뀜.
  오타를 고쳐 노드 8개로 돌리면 노드 상태가 −1 → 15 → −2 → 14 … 로 진동.
  (`cfea_core.v` 는 상수를 `signed` 로 선언해 이 문제가 없지만, 최상위 모듈은 이 모듈을 쓰지 않음)
- **테스트벤치 타이밍 경쟁**: 클록 상승 순간에 입력을 바꿔, (4,5)에 쓰려던 결합값이 (0,0)에 기록됨
  (자기 결합 생성). (4,5)에는 기록되지 않음.
- **테스트벤치가 확인을 하지 않음**: "Symmetry Lock verified" 는 결과와 무관한 고정 문장.
- **주소 폭**: 노드 번호 5비트 → NODE_COUNT=100 중 32개까지만 결합값을 쓸 수 있음.
- **초기 상태 적재 경로 없음**: 리셋 시 모든 상태 0.
- **구조 불일치**: RTL 은 모든 노드 쌍을 곱하는 조밀 연결(노드 100개에 곱셈 1만 개). 4,096노드 메시 주장과 다름.
  iverilog 로 노드 100개 설계를 펼치는 데만 200초 이상 걸림.

### 파이썬
- **937ns, 625MHz 는 측정값이 아님**: `cfea_pipeline_sim.py` 에서 293사이클(출처 없는 고정값) × 2(주석상 "가정")
  × 1.6ns(고정값). 같은 스크립트의 단일 사이클 결과(747ns)보다 파이프라인(937.6ns)이 25% 느린데
  "동등한 성능 유지"로 출력.
- **타이밍**: `cfea_max_frequency.py` 의 게이트 지연은 직접 정한 상수. 합계 2.55ns = 392MHz.
  1.6ns 단(stage)은 어디서도 계산되지 않음.
- **PPA**: 게이트 수와 활동 계수를 가정한 계산이며 합성이 아님. 그 가정대로면 동작 중 약 3.2W.
- **수렴 반례**: 4,096노드 메시에서 시드 0–3 은 1,003–1,300사이클에 수렴, **시드 4 는 2만 사이클 동안
  노드 12–13개가 계속 변하며 수렴하지 않음**. 메시 스크립트는 최대 반복 한도(1000)에 걸린 것을
  "수렴 완료"로 출력.
- **에너지 함수**: 코드의 `-½aᵀWa - aᵀθ` 는 이 동역학의 리아푸노프 함수가 아님
  (홉필드 연속 모델의 에너지에는 누설 항에 해당하는 적분 항이 있음). 그래프는 수렴의 증거가 되지 못함.
- **자가 치유 시험**: 공격으로 넣은 바이어스가 제거되지 않고, 공격 전 상태와 비교하는 코드가 없음.
  결론 문장은 결과와 무관하게 고정 출력. 에너지 그래프에서 공격 순간(100사이클) 에너지가 급락하는 것은
  회복이 아니라, 공격 바이어스(+8.0)가 에너지 식의 `−aᵀθ` 항을 크게 음수로 만들어 **문제 자체가 바뀌었기
  때문**이며, 이후 곡선은 바뀐 문제에 다시 정착하는 과정이다.
- **대칭 방어 시험**: 보호 시나리오에서도 악성 값 자체는 (대칭으로) 기록됨. 대칭은 수렴 성질을 지킬 뿐
  내용의 무결성을 지키지 않음.

## 선행기술 (1차 조사, 논문·공개 자료 중심)

| 요소 | 가장 가까운 기존 기술 |
|---|---|
| 연속 상태 + 대칭 결합 + 에너지 하강 | Hopfield, PNAS 81, 3088 (1984) — 방정식 구조가 사실상 같음 |
| 고정소수점 적분하는 병렬 디지털 이징 하드웨어 | Toshiba FPGA 시뮬레이티드 분기 머신 (FPL 2019, 4,096 스핀) |
| SRAM 기반 메시, "물리적 수렴으로 푸는" 비 폰 노이만 칩 | Hitachi CMOS 어닐링 칩 (ISSCC 2015, 2만 스핀) |
| 모든 노드 동시 갱신 | Hitachi STATICA, 연속 시간 이징 머신 연구 |
| 수렴 후 클록 차단 | 일반적인 클록 게이팅 기법 |
| 폴디드 토러스 배치 | 네트워크온칩의 배선 길이 균등화 기법 |
| 글로벌 기저 상태 복구 | 오히려 홉필드형 시스템은 국소 최솟값에서 멈출 수 있다는 것이 알려진 한계 |

특허 데이터베이스(KIPRIS 등)는 깊이 검색하지 않음.

## 접은 이유

1. 핵심 요소 대부분이 공지 기술이다.
2. 핵심 주장(결정론적 수렴, 글로벌 기저 상태 복구)에 반례가 있거나 기존 지식과 충돌한다.
3. 성능 수치가 측정이 아닌 가정에서 나왔다.
4. 출원을 줄이고 IESA 에 집중하기로 했다.

## 다른 곳에서 다시 쓸 것

- 연속 상태(홉필드형) 동역학 → IESA 연구에서 물리 기반 기준선으로 비교
- 토러스 메시 생성과 4방향 로컬 가중치 저장 → 격자 문제용 고정 칸 저장 방식 참고
- 실행 중 공격(오염) 주입 시나리오 → IESA 오류 주입 실험의 출발점 (공격 전후 상태 비교를 추가해서)
- 배운 것: 부호 있는/없는 수 비교 함정, 테스트벤치의 클록 경쟁, 결론을 고정 문자열로 출력하지 않기,
  그래프의 축 이름이 주장하는 것(예: "Lyapunov")이 실제로 그 양인지 확인하기
